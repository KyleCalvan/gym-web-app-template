# Domain docs

## Layout

This repo uses a single-context layout:

- `GLOSSARY.md` at the repo root: domain vocabulary.
- `docs/adr/`: architecture decision records.

## Before exploring

Read the glossary and ADRs relevant to the work.

If these files do not exist, proceed silently. The domain-modeling
skill creates them lazily when terms or decisions are resolved.

## Vocabulary

Use glossary terms consistently in issues, proposals, hypotheses,
and test names. For missing terms, reconsider invented vocabulary
or note the gap for domain-modeling.

## Decision conflicts

Explicitly identify any proposal that contradicts an existing ADR,
cite the ADR, and explain why the decision merits reconsideration.
